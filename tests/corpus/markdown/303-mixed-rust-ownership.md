# Rust 所有权：借用检查、生命周期与零成本抽象

Rust 最与众不同的地方在于它把内存安全交给了编译期，而不是 GC。所有权（ownership）规则只有三条，却几乎解释了语言里所有看起来「别扭」的写法：每个值有唯一所有者、同一时刻只能有一个所有者、所有者离开作用域时值被 drop。理解了这三条，借用检查器（borrow checker）就不再像一个爱挑刺的裁判。

## 移动与借用

赋值默认是移动（move）而非拷贝（copy），这也是为什么把一个 String 传给函数后，原来的变量就失效了。

```rust
fn consume(s: String) {
    println!("{}", s);
}

fn main() {
    let name = String::from("ferris");
    consume(name);
    // 这里再用 name 会编译失败：value moved
}
```

如果不想交出所有权，就用引用借用（borrow）。不可变引用 `&T` 可以有任意多个，但可变引用 `&mut T` 同一时刻只能有一个，这条规则在编译期消灭了数据竞争。

| 引用形式 | 数量限制 | 能否修改 |
| --- | --- | --- |
| `&T` | 任意多个 | 否 |
| `&mut T` | 同一时刻仅一个 | 是 |

## 生命周期标注

生命周期（lifetime）标注不是为了改变值的存活时间，而是把「输入与输出之间的借用关系」告诉编译器。大多数情况下省略规则（elision）已经够用，只有在多个输入引用竞争同一个输出位置时，才需要显式写下 `'a`。

> 编译器不会发善心延长一个值的生命，它只会要求你证明引用活得比借用更久。

## 零成本抽象

零成本抽象（zero-cost abstraction）的意思是：高层写法在编译后不会比手写底层代码更慢。迭代器链就是典型例子，适配器会被内联并消除中间分配，最终生成的机器码和手写循环几乎一致。

1. 先用最直白的迭代器表达意图；
2. 用 benchmark 确认热点；
3. 只有确实必要时才下沉到 unsafe 或裸指针。

需要提醒的是，抽象并非绝对免费：单态化（monomorphization）会让每个泛型实例都生成一份代码，从而放大编译时间与二进制体积。在体积敏感的场景里，用 `dyn Trait` 做动态分发反而是更划算的取舍。

## 小结

所有权、借用与生命周期，本质上是同一套规则的三种视角。让编译器替你把关，付出的只是写代码时的思考成本，换来的却是运行时的零开销与零数据竞争。
