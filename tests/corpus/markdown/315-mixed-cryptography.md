# 应用密码学：对称加密、非对称加密与哈希签名

应用密码学（applied cryptography）最重要的原则是：不要发明自己的算法，也不要用错现成的算法。这篇文章只谈三个最常被误用的基础构件——对称加密、非对称加密，以及哈希与数字签名。

## 对称加密

对称加密（symmetric encryption）的加解密使用同一把密钥，速度快，适合保护大量数据。它的软肋在于密钥分发：双方如何安全地共享这把密钥。

- AES-GCM 同时提供机密性与完整性，是当下的默认选择；
- 绝对不要使用 ECB 模式，它会把相同明文块加密成相同密文块，泄露结构；
- 每次加密都应使用独一无二的随机 nonce，重复 nonce 会让 GCM 的安全性彻底崩塌。

| 模式 | 是否认证 | 是否推荐 |
| --- | --- | --- |
| ECB | 否 | 否 |
| CBC | 否 | 需配合 HMAC |
| GCM | 是 | 是 |

## 非对称加密

非对称加密（asymmetric encryption）使用公钥与私钥一对密钥，解决了密钥分发难题。常见的 RSA 与椭圆曲线（ECC）各有场景：ECC 在同等安全强度下密钥更短、运算更快。

> 公钥可以公开，私钥绝不能离开生成它的设备。

非对称运算很慢，因此实际协议里它通常只用来协商一把临时的对称密钥，之后的通信再切换到对称加密——这正是 TLS 握手的基本思路，也体现了混合密码系统（hybrid cryptosystem）的价值。

## 哈希与签名

哈希（hash）函数把任意长度输入映射成固定长度摘要，要求单向、抗碰撞。它用于校验完整性，但绝不等于加密，因为无法还原原文。

```text
password + salt  ->  bcrypt  ->  stored digest
```

存储口令必须使用专门的慢哈希（如 bcrypt、scrypt、argon2），并给每个用户分配独立盐值，从而抵御彩虹表与批量爆破。

数字签名（digital signature）则是「用私钥签名、用公钥验证」，同时保证完整性与来源可信。

1. 发送方对消息摘要计算哈希；
2. 用私钥对摘要签名；
3. 接收方用公钥验证签名是否能还原出相同摘要。

它天然提供了不可否认性，但也要求密钥管理做到位：私钥一旦泄露，签名就失去了全部意义。

## 小结

对称负责快，非对称负责分发，哈希负责摘要，签名负责可信。把它们按正确的协议组合起来，才是可用的安全系统。
