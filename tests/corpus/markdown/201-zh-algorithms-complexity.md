# 算法复杂度导论

复杂度分析是描述算法随输入规模增长时资源消耗如何变化的语言。它刻意忽略常数因子与低阶项，因为当规模足够大时，这些因素都会被主导项淹没。但要记住，忽略不等于无害：在真实工程中，一个常数很小的线性算法常常胜过常数巨大的对数算法。

## 渐进记号

人们常用的三种记号各有明确含义。

- 大 O 记号给出上界：存在常数与阈值，使得超过阈值后函数不超过某倍数。
- 大 Omega 记号给出下界：函数不会低于某个倍数。
- 大 Theta 记号同时给出上下界，刻画紧确的增长率。

口语中常说的“这个算法是 O(n)”其实多半指的是 Theta，严谨表述与日常用法之间存在长期的习惯性偏差。

## 常见复杂度阶

从快到慢，常见的阶大致如下。

1. 常数级：与规模无关，典型如数组下标访问。
2. 对数级：每次把问题规模减半，如二分查找。
3. 线性级：遍历一遍输入。
4. 线性对数级：高效比较排序的下界。
5. 平方级：朴素的双重循环，如冒泡排序。
6. 指数级与阶乘级：组合枚举，规模稍大就不可行。

排序问题的下界一直是教学重点：任何基于比较的排序都至少需要线性对数次比较，因为判定树的高度给出了这个界限。

## 摊还分析

有些操作偶尔昂贵，但整体便宜，这时用最坏情况描述单次操作会过于悲观，而平均情况又需要概率假设。摊还分析提供了第三种视角。

常见的三种手法是聚合分析、记账法和势能法。以动态数组的尾插为例，扩容那一次搬移了全部元素，代价是线性的；但把总代价摊到此前所有插入上，每次插入的摊还代价仍是常数。

> 摊还保证与平均情况保证并不等价。前者对任意操作序列都成立，后者依赖输入分布。混淆两者是性能估算中最常见的错误之一。

## 分析中的陷阱

输入规模的度量本身就是选择。图算法中，规模既可能指顶点数，也可能指边数，用单一变量描述会丢信息。此外，模型假设也很关键：把乘法当作常数时间，在涉及大整数运算时就会失效。

## 小结

- 用渐进记号描述趋势，用实测数据校准常数。
- 区分摊还保证与平均情况，前者对任意操作序列都成立。
- 明确规模的度量方式，否则复杂度结论没有意义。

把这三条习惯固定下来，性能讨论就会从主观争辩变成可验证的推理。

最后，渐进分析只描述趋势。当实际数据规模很小，或者存在明显的缓存效应时，趋势之外的因素可能完全主导运行时间。理论分析与实测数据应当互为补充，而不是互相替代。
