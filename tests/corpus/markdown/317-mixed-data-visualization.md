# 数据可视化：编码通道、坐标轴与可访问配色

数据可视化（data visualization）的本质是把数据映射到视觉变量上，这个过程叫视觉编码（visual encoding）。图做得是否好用，往往不取决于配色多漂亮，而取决于你是否为每份数据选了合适的编码通道（encoding channel）。

## 编码通道的优先级

通道分位置、长度、角度、面积、颜色等。人眼对不同通道的辨别精度差异巨大，这决定了选择的优先级。

- 位置与长度：最容易精确比较，应优先用于最重要的量；
- 角度与面积：只能做粗略估计，适合次要维度；
- 颜色饱和度与明度：擅长表达连续量，但要慎用色相表达数值。

| 通道 | 感知精度 | 适合表达 |
| --- | --- | --- |
| 位置 | 高 | 主数值 |
| 长度 | 高 | 条形比较 |
| 面积 | 中 | 气泡大小 |
| 色相 | 低 | 类别区分 |

一个常见的错误是同时用色相和大小表达同一个量，结果两个通道互相干扰，读者反而看得更累。

## 坐标轴与刻度

坐标轴（axis）承载着读者对数值的参照。柱状图的纵轴原则上必须从零开始，否则会人为放大差异；折线图为了展示变化趋势，允许截断，但必须清楚标注。

> 截断轴本身不是作弊，偷偷截断而不标注才是。

刻度间隔要选人类易读的整数，避免出现 3.7、7.4、11.1 这样的边界。对于跨数量级的数据，对数轴（log scale）能让小值不被压成一条线，但也容易让不熟悉的读者误读倍数关系，因此要在标题或注释里说明。

## 可访问配色

配色首先要考虑色觉障碍（color vision deficiency），大约每十二个男性里就有一个受到影响。

1. 不要只用红绿对比来区分「通过/失败」，改用明度差或叠加形状标记；
2. 保证前景与背景的对比度达到 WCAG 推荐值；
3. 使用连续色带时优先选感知均匀（perceptually uniform）的方案，避免亮度在中间塌陷。

配色还需要注意打印场景：纯靠饱和色区分的地图，一旦转成灰度就可能完全糊在一起。

## 标注与克制

图表的默认状态应该让读者一眼看懂「什么在变化」。去掉多余的网格线、去掉三维特效、去掉与结论无关的装饰。标题要写出结论而不是复述坐标轴，注释则用来解释异常点背后的原因。数据墨水比（data-ink ratio）这个老概念至今不过时：能用更少的视觉元素传达同样的信息，就是更好的图。

## 小结

选对通道、标对坐标、配好颜色、少做装饰。可视化的功力，一半在数据，一半在克制。
