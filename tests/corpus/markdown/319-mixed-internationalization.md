# 国际化：区域设置、复数规则与双向文本

国际化（internationalization，i18n）的目标是让同一份产品适配不同语言与文化，而本地化（localization，l10n）则是为某个具体市场落地。二者常被混为一谈，但工程上的关注点完全不同：前者是架构能力，后者是内容生产。

## 区域设置

区域设置（locale）通常写成 `language-REGION` 的形式，比如 `zh-CN`、`en-US`、`pt-BR`。语言相同但区域不同，差异可能很大。

- 日期格式：美式是先月后日，而多数地区是先日后月；
- 数字格式：千位分隔符与小数点符号在部分区域正好相反；
- 首周定义：一周从周一还是周日开始，也会影响日历组件。

| locale | 日期示例 | 数字示例 |
| --- | --- | --- |
| en-US | 3/14/2026 | 1,234.56 |
| de-DE | 14.3.2026 | 1.234,56 |
| zh-CN | 2026年3月14日 | 1,234.56 |

因此日期与数字绝不要手写格式化逻辑，应统一交给平台提供的 Intl API 或成熟的库处理。

## 复数规则

复数（plural）远不是「加个 s」这么简单。不同语言的复数类别数量差异极大：英语只有 one 与 other 两类，阿拉伯语则有 zero、one、two、few、many、other 六类。

> 复数规则属于语言，不属于数字；判断分支要依据 locale，而不是简单比较是否等于 1。

```json
{
  "items": {
    "one": "{count} item",
    "other": "{count} items"
  }
}
```

翻译文案里也要避免拼接句子片段，因为不同语言的语序不同，把「你还有」和「条消息」分开翻译，再拼起来几乎必然出错。变量占位与整句翻译，才是可维护的做法。

## 双向文本

双向文本（bi-directional text）指同一段内容里混用从左到右（LTR）与从右到左（RTL）两种书写方向，阿拉伯语、希伯来语都属于后者。

1. 布局层面使用逻辑属性（logical properties），如 margin-inline-start 取代 margin-left；
2. 文本方向由文档或元素上的 dir 属性声明，不要靠 CSS 猜测；
3. 混排数字或英文品牌名时，必要时用隔离字符（isolate）避免方向串位。

镜像图标（mirrored icon）也要跟着翻转：返回箭头在 RTL 布局里应当指向右侧。同时要预留文本膨胀（text expansion）空间——同样的意思翻成德语往往长出一大截，按钮和标签都要能自适应。

## 小结

区域化格式化交给标准库，复数与语序交给翻译规则，方向与布局交给逻辑属性。把这三层分开，i18n 才不会变成到处打补丁。
