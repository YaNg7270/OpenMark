# 中文技术写作中的表格

在中文技术文档里，表格常用来对比几种方案、罗列参数取值，或者总结那些容易被混淆的概念。下面的表格用三列分别给出名称、主要用途和典型场景，每一格都是一句完整的中文句子。

| 名称 | 主要用途 | 典型场景 |
| --- | --- | --- |
| 令牌桶 | 以固定速率发放令牌，从而限制长时间内的平均流量。 | 对外 API 网关的入口限流。 |
| 漏桶 | 以恒定速度取出请求，用于平滑突发流量带来的抖动。 | 消息队列的消费端。 |
| 滑动窗口 | 按时间窗口统计请求数量并丢弃超出配额的部分。 | 以单个用户为维度的限流。 |
| 信号量 | 限制同时进入临界区的并发数量，从而保护下游资源。 | 数据库连接池的容量控制。 |

上表每一行都描述一种常见的限流算法，句子之间用逗号连接，尽量避免在单元格里插入竖线或换行。表格前后各留一个空行，可以让大多数编辑器稳定识别列边界。

如果某一格确实需要分层说明，更稳妥的做法是把句子写短一些，而不是强行塞入 HTML 标签。保持单元格内容为纯文本，是让表格在不同渲染器之间表现一致的最简单办法。

中文标点在小屏幕上同样需要注意。全角逗号和顿号会占用更宽的像素，因此列宽估算应当以实际字形宽度为依据，而不是简单地按字符个数平均分配。

中文文档还有一个常见问题：全角标点与半角标点混用。表格里的数字通常使用半角，标点使用全角，这一点应当写进写作规范，否则不同作者产出的文件看起来会很不一致。

另一个细节是术语的中英对照。第一次出现时给出英文原词，之后只用中文，可以在可读性与检索准确性之间取得平衡，这也是技术写作里比较成熟的做法。

表格的行数不必刻意凑整。四行或五行都可以，只要每一列的含义保持稳定，读者就能迅速建立心理模型，而不必反复回看表头。

如果同一张表格被多个章节引用，最好把它固定在一个地方，再用链接指向它。复制多份容易在后续修改时产生分歧，最终导致数据自相矛盾。

排版工具对中文单元格的换行策略也各不相同，有的按字符宽度折行，有的优先在标点处断行，因此测试时应当同时检查渲染结果与解析结果，而不只是看第一眼的观感。

限流算法的名称在不同团队里可能略有差异，但含义大同小异，写文档时最好在第一次出现处给出全称，后续再使用简称。

表格的最后一列通常是备注，可以放一些不便归类但又有用的信息，不过备注不宜过长，否则会挤压前面的列宽。

最后需要提醒的是，中文表格在版本控制里的差异往往比英文更长，因为一行可能包含大量字符。因此改动时应当尽量只修改真正需要修改的那一格。

还需要注意中英混排时的空格问题。许多排版规范建议在中文与拉丁字母之间插入一个空格，这样阅读起来更舒适，也便于后续的自动检查工具统一处理。

本文件只包含一张表格，目的是让测试可以精确断言行数与列数，而不受其他结构干扰。

保持示例简洁，本身就是一种可维护性。

只要表头与每一行的列数一致，解析器就不需要任何额外的提示信息。
